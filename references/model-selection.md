# Model selection

Use the current host's same-context catalog. Advertised support, confirmed account access, availability and observed execution are separate evidence. A model name prefix or a complete provider API list cannot establish host support.

Start with a verified host default when comparative evidence is weak; preserve unresolved selection when even that evidence is missing. `balanced`, `quality`, `economy` and `fast` express goals, not a hardcoded model ranking. Use `orch_model_recommend action=preview` for validated role selections and a patch. Apply with that preview's config and recommendation hashes so refreshed metadata cannot silently change the approved proposal. Profile selection requires supported current-host metadata plus a verified default or evidence-backed quality/latency/usage assessments; no evidence means no invented new-model patch. Choose capabilities for the task: planning and review need reasoning appropriate to complexity; repetitive implementation needs demonstrated adequate quality. Preserve explicit overrides. Change `auto` fields only, record reason, affected attempt, config revision and any observed budget impact.

Query every available catalog page; preserve lookup errors and stale-cache provenance. Context mismatch or unknown access prevents claiming verified selection. Do not probe every candidate with billable requests. No catalog means no invented recommendation. Resolve `auto` before dispatch and represent `inherit` as parent policy when the actual parent ID is unavailable.

Refresh same-context native metadata through `orch_host_refresh` with authenticated physical Git identity before recommending from changed host information; retain prior receipts. Record requested, resolved and observed model/effort independently. Unknown actual model, tokens or price stays null. A test fixture's verified capability is not production host proof. Never reduce required tests/review or switch providers as a usage optimization.

The current registry persists unknown-scope disk metadata under the ORCH global config directory’s `cache/models/unknown/<host>/`. Its key includes executable/version, origin and local settings/environment fingerprints, but account/workspace/policy identity remains unknown. `source`, `stale`, fetch/expiry timestamps and `errors` distinguish live/cache/failure. `refresh=true` requests a refresh; a failed refresh may return stale cached entries with the failure. Cache presence never promotes `contextMatches=false` to a current-session match.

Actual native invocations consume the prepared per-role model/effort. Separate read-only reviewer/final-auditor dispatches retain their own configuration revision and model receipts. A supported request passed to a host is not an observed actual value. Record nonnull observations even when inherited resolution was unknown; report policy clamping or mismatch explicitly and preserve genuine violation checks.

## Native metadata for configuration

An empty Claude subprocess catalog with `NATIVE_MODEL_METADATA_UNAVAILABLE` means no existing-session metadata adapter was supplied. Installation alone does not supply that SDK session. It does not prove the current conversation lacks an `Agent` tool: inspect the actual current-host tool schema before treating detection-time `unknown` as unsupported.

For an explicit model edit, inspect the current native Agent tool's declared model options or an already available current-session metadata API. Use only options and provider-family information actually exposed there. A free-form model parameter alone is not a catalog; model names recalled from memory, another host's catalog, and repository-supplied descriptors are not evidence. Keep `model_selection.allow_unverified_models: false` and `allow_cross_host: false`; both are false-only schema constraints, not switches to offer as a workaround. Preserve the file when required metadata is unavailable and report the exact missing field/tool or error instead.

When actual current-host model metadata is available and the explicit edit needs it, perform the [native connection](workflow.md#native-connection) read-only Git challenge using the real `Agent`/`spawn_agent` tool, then relay the metadata in authenticated `orch_host_connect.native_context` (or `orch_host_refresh` for an existing connection). This configuration route creates no run or implementation worker. Reuse the active connection when valid. A preview request can establish this ephemeral read-only connection but never writes configuration; an explanation/no-tools request does not launch a probe. Keep tokens in the parent and verify the physical project root first.

Each relayed descriptor uses the actual tool/API option as `id`, its host and explicitly supported family, `source` and `evidence` identifying that tool/API, and the real retrieval time. Preserve advertised status and unknown access/availability. Unknown resolved ID, effort levels, defaults or expiry remain null. Populate `native_context.model` and `effort` only from actual current-parent metadata; otherwise use null, never the requested role selection. Set per-invocation capability flags from the actual callable parameters, not from the subprocess detector or a successful Git probe. Model selection support does not imply effort selection support. A native alias is a host selector, not an observed provider model ID.

Reread `orch_models.authenticatedNative` and preview the requested role patch through `orch_config`; a matching advertised descriptor can validate saving without proving account access or dispatch readiness. For a model-only edit, keep existing `auto`/`inherit` effort policies unchanged. Preserve an explicit effort only when its level is supported; otherwise explain the conflict and obtain the user's choice rather than silently replacing it with `inherit`. Explicit effort values require their own supported-level evidence. Automatic optimization still requires the Advisor's native invocation/default or comparative evidence. Report requested, resolved and observed separately; configuration success never establishes actual backend execution.

`orch_models.authenticatedNative` exposes current parent-relayed metadata separately from the subprocess catalog/cache. Check `orch_environment.nativeControl.perInvocationModel` / `perInvocationEffort` before claiming a concrete recommendation is executable. The public Advisor emits no concrete pin patch without model invocation support and, when the selected default effort needs it, effort invocation support. A catalog listing alone cannot supply those capabilities.

Measured Advisor inputs are authenticated parent attestations, not built-in evaluations or price data. `quality` maximizes supplied quality, `fast` minimizes supplied latency and `economy` minimizes supplied usage, using the referenced observations only. Preserve fixed scope values and report measurement limits; a synthetic fixture comparison does not establish actual host performance or cost savings. Supply the same `assessments` on preview/apply so approval remains bound to the exact evidence.
