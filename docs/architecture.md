# Architecture

The current host conversation is the coordinator. `skills/` provides two common entry sources; installer-generated copies target Codex, Claude and Hermes without maintaining divergent workflow text. Shared `references/` files are copied into each installed skill's `references/` directory. The source skill links target that generated installation layout.

`packages/protocol/` validates config, plans, reviews and mutation envelopes. `packages/core/` owns layered config, model normalization, SQLite state/journal, repository identity and deterministic run operations. `packages/host-codex/` and `packages/host-claude/` supply metadata; metadata access is not native dispatch. `packages/mcp-server/` exposes tools/resources over stdio. `packages/installer/` owns diagnostics and managed installation.

State belongs to the invocation origin `.orch/state/`, with a common-Git-directory lock to coordinate linked checkouts. Worker worktrees live outside the origin checkout. Operations carry idempotency identity and expected state version; commit/merge intent supports reconciliation. Each run pins its immutable runtimeRoot; a different installation version can inspect status but cannot resume mutation. New attempts pin config revision and requested/resolved policy without changing prepared attempts. Reviews and gates are tied to source SHAs; canonical gate results include fingerprints, timestamps and redacted log references. Reports are read-only by default and explicitly persisted under the run’s reports directory. Coordinator-token relay guards management mutations at the application layer.

The production MCP begins without native capability, then accepts authenticated parent receipts tied to a real native probe and exact Git context. Per-role preparation resolves model/effort and returns actual native arguments; read-only reviewer/final-auditor dispatches retain independent receipts and stop evidence. Distributed role templates do not establish model application, reload or OS permissions. Unit fixtures exercise these contracts without proving native E2E. [Compatibility](compatibility.md) records that boundary.

The catalog service caches metadata in an explicitly unknown identity scope with expiry, errors and provenance. It cannot establish account/policy/current-session equivalence. Authenticated current-host model metadata is exposed separately from that subprocess cache. Metadata or daemon reachability alone cannot establish current-session native invocation support; the current conversation relay does not require a daemon socket. See [acceptance](acceptance.md) for local implementation limits separately from missing native/OS evidence.

Requirements submission persists a validated canonical contract before planning; plan acceptance must exactly match it. MCP session config is an isolated in-memory layer with hash/revision and dry-run, consumed by run creation and later attempts. Explicit gate waivers retain reason and snapshot identity, while run-scoped finalization consent remains separate from config. Active timeout excludes explicit pauses and repeated findings require recorded analysis before bounded repair continues.

Immutable database snapshots retain config/catalog/model/attempt history and redacted values with original-input identity hashes. Semantic events and regenerated request/plan/config/snapshot exports support recovery; exported files are derived views. The engine and report share a conservative completion oracle. Authenticated liveness receipts never extend fixed attempt deadlines, and cleanup preserves uncertain writing or read-only workers.
